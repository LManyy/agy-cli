# `agy` 与 `codex` 高效协同规范

本规范用于指导 `agy`（总控 / 架构与验收）通过 MCP（`codex_run` / `codex_reply`）高效调度 `codex`（执行 / 实现 / 只读审查）。

---

## 1. 角色边界与独立判断原则（核心）

- **`agy` 是唯一决策者，不被 `codex` 语气带偏**：
  - `codex` 的回复通常带有过度谨慎、防御性免责声明、或“建议用户再确认/可能存在未知风险”等保守措辞。
  - **`agy` 必须忽略其情绪化与防御性免责部分，只提取客观事实**（改了哪些文件、跑了什么命令、退出码与测试输出、实际报错）。
  - 方案是否合理、修改是否达标、是否需要返工或向用户汇报，**完全由 `agy` 依据真实代码、实际 `git diff` 和命令输出独立判断**，不得因为 `codex` 过度保守而盲目推翻已定方案，也不得因为 `codex` 声称“已完成”而跳过验收。

---

## 2. AI 间高信息密度派单格式（`codex_run` / `codex_reply`）

避免寒暄与模糊描述，每次派单直接按以下结构给出机器友好的精确上下文：

```text
[Goal] 一句话明确本次唯一目标
[Scope] 仅允许修改/关注的文件或模块列表（未列出的文件勿动）
[Constraints] 技术约束、代码风格、禁止事项（如不新增依赖、保留注释）
[Verification] 完成后必须执行的校验命令（如 pytest / ruff / py_compile）
[Output] 仅返回：修改文件清单、校验命令及真实输出、未解决的阻塞点
```

### 派单纪律
1. **控制粒度与超时红线（1~2 文件原则）**：单次 `codex_run` 仅限修改 **1~2 个目标文件**（或单独编写 1 个测试文件），禁止把“多参考文件阅读 + 多模块实现 + 集成测试”打包成大单；`timeout_sec` 建议设置为 `150`~`170`（低于 MCP 180s 硬上限）。若发生超时，先查看日志末尾与工作区已写入文件，将剩余部分拆成更小单子接续，禁止原样重试。
2. **架构先行与风格锁死**：新增复杂功能前，先由 `agy` 完成目录拆分与接口预留；`[Constraints]` 中必须写明项目代码风格（如 Python 版本、类型注解、中文 docstring 习惯）及**禁止将业务逻辑堆回核心调度文件**（如 `bot.py`）。
3. **必须命名会话（`name`）**：调用 `codex_run` 时传入简短语义化 `name`（如 `auth-fix`、`unit-test`），便于并发时区分各自日志与结果。
4. **先给定关键路径**：`agy` 已知的文件路径、符号名、参考文件位置、报错行号直接写入 `[Scope]`，避免 `codex` 重复全库扫描浪费时间与额度。
5. **多轮返工必用 `codex_reply`**：利用 `codex_run` 返回的 `session_id` 追问或修复，不重复开新会话重读上下文。

---

## 3. 验收与冲突控制

- **先看实际代码与测试输出，再下结论**：`codex_run` 返回后，`agy` 应核查实际文件变更与测试结果，确认无多余改动、无遗漏边界。
- **Codex 盲区必查清单（第三阶段强制 Review）**：
  1. **跨模块联动**：新增命令或功能是否同步更新了 `/help`、交互菜单按钮、`setMyCommands` 等外围入口。
  2. **交互体验细节**：按钮回调触发提示时，是否利用已有 `message_id` 原地 `edit_message_text`（而非多发冗余气泡）；独立消息是否保持统一的底部按钮与多字段拼接。
  3. **防御性边界**：调用外部 API/子进程返回值（如 `send_one` 返回的 `message_id`）是否做了类型与判空保护，超时/异常路径是否释放锁与文件描述符。
  4. **实现一致性**：局部变量引用与错误处理风格是否前后统一。
- **严禁并发写同一目录**：同一时间同一工作区只允许 `agy` 或单个 `codex` 写入；多任务并行必须先隔离目录（如 `git worktree`）。
- **小改动不派单**：10 行以内的小修改或纯查询由 `agy` 直接完成，不经过 MCP 派单。

---

## 4. 越界与审批处理约定

- 默认仅使用 `sandbox="read-only"`（纯分析/Review）或 `sandbox="workspace-write"`（编码/单测）。
- 若 `codex` 因沙箱限制无法执行工作区外操作、联网安装依赖或高危命令，**禁止尝试绕过**，应直接返回“被拦截的具体命令与原因”；由 `agy` 评估必要性后，决定由 `agy` 自身发起工具调用（触发原生终端审批弹窗交由用户确认）或提示用户处理。
